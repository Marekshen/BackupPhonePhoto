# 照片備份到 Google Drive

以 iPhone 為主（Windows 也可使用）的 PWA，將照片與影片批次備份到指定的 Google Drive 資料夾。

網址：https://marekshen.github.io/BackupPhonePhoto/

## 功能

- Drive API v3 上傳（小於 5MB 一次送出，較大檔案分段續傳），同時上傳 4 個
- 暫停、繼續、失敗自動重試（指數退避）
- 以檔案指紋避免重複上傳
- 上傳後以 SHA-256 與大小比對本地與 Drive 檔案是否一致
- Drive 的建立／修改日期設為拍攝時間

## 已知問題與限制

### 檔案格式

- **HEIC 會變成 JPEG**：iOS Safari 選取照片時會自動轉成 JPEG，因此檔案大小與 iPhone 顯示的不同。上傳的是轉檔後的檔案。
- **Live Photo 只會上傳靜態照片**：網頁拿不到 Live Photo 的影片部分。
- **檔案大小顯示差異**：iPhone 以 1MB = 1,000,000 bytes 顯示，Drive 以 1MB = 1,048,576 bytes 顯示，同一個檔案數字會不同。

### 縮圖方向

- 在 iPhone 上旋轉過的照片，Drive **列表縮圖**可能顯示未旋轉的方向，但打開照片的預覽是正確的。
- 原因：iPhone 給網頁的檔案可能只帶「方向標記」而未實際旋轉像素，Drive 產生縮圖時未套用該標記。
- 不修正：修正需要重新壓縮照片，會降低畫質，也會使檔案與原檔不一致。

### 拍攝時間

依序採用以下來源：

1. 照片 EXIF 或影片的 Apple 拍攝時間
2. 檔名中的時間（例如 `ScreenRecording_06-27-2026 17-14-45.mov`、`20240501_102030.jpg`）
3. 影片內部的建立時間
4. 檔案修改時間

已知情況：

- **螢幕錄影、剪輯 App 匯出的影片**（例如 `copy_xxxx.mov`）：通常沒有拍攝時間，影片內部時間也是 iOS 交給網頁時重新匯出的當下。
- **沒有可靠時間的檔案**：會沿用同批選取中前一個有可靠時間的檔案；前面沒有就用後一個；前後都沒有則維持上傳當下的時間。這只是近似值，依選取順序而定。
- **建立日期無法事後修改**：Google 只允許在上傳時設定建立日期。已上傳的檔案重新選取時只會修正修改日期。請在 Drive 以「上次修改時間」排序。
- 照片 App 中顯示的日期存在其資料庫中，網頁無法讀取。

### 使用限制

- **上傳期間需保持畫面開啟**：切換 App 或鎖定螢幕會中斷，回到頁面後會自動續傳。
- **登入有效約 1 小時**：過期後需重新登入，登入會重新載入頁面，已選取的檔案需重新選取（已上傳的不會重傳）。
- **重新整理頁面會清空上傳清單**。
- **只看得到本工具建立的資料夾**：使用 `drive.file` 權限，無法存取 Drive 中其他檔案。
- **比對不一致不會自動處理**：顯示「不一致」的檔案需自行確認；重新選取時會被判定為「已存在」而不會重傳。

## 開發

```bash
npm install
npm run dev
npm test
npm run build
```

推送到 `main` 後由 GitHub Actions 部署到 GitHub Pages。Google OAuth Client ID 設定在 repo 變數 `GOOGLE_CLIENT_ID`。
